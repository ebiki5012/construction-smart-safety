스마트 안전관리 V7 통합 개선판 — 2026-11-16
============================================

이 압축파일은 V7 1차판의 전체 파일을 바탕으로 만든 통합 개선본입니다.
기존 서버/화면 파일을 같은 경로에 덮어쓰는 방식입니다.

[이번 통합판에 들어간 기능]

1. 왼쪽 업무별 하위 메뉴
   - 위험성평가: 작성 / 주차·업체별 조회 / 주간 통합 결재 / 승인 완료 / 표준평가
   - TBM: 작성 / 일자별 조회 / TBM 결재함
   - 지적·조치관리: 지적 등록 / 미조치 / 조치 확인
   - 협력업체·작성자 관리: 현장관리자 및 최고관리자에게 표시
   - 사진보관함: 출처·원본 업무 기록 바로가기
   - 최고관리자는 사용자 지정 양식을 위험성평가·TBM·지적조치의 하위 메뉴로 배치 가능

2. 주간 통합 위험성평가
   - 주차 시작일은 월요일. 각 위험요인의 적용기간과 겹치는 주차에 취합
   - 협력업체 직원이 작성하고 [협력업체 작성 완료 제출]로 완료 표시
   - 원청 현장관리자가 업체별 제출 상태 확인 후 주간 평가서 전체를 한 번에 상신
   - 미제출 업체가 있으면 경고하며, 원청 관리자는 명시적 확인 후 상신 가능
   - 현장관리자가 최고관리자센터에 들어가지 않고 승인/반려
   - 반려 후 수정하여 재상신 가능. 차수별 평가내용 스냅샷 및 결재 이력 보존
   - 보고서 열기 -> 브라우저 [인쇄] -> [PDF로 저장]

3. 협력업체 / 사용자 / 현장
   - 현장별 협력업체 등록, 현장 사용자 계정과 업체 연결
   - 협력업체 직원은 지정된 업체로 직접 작성(임의로 다른 업체 선택 불가)
   - 원청 관리자는 업체를 선택해 대리 작성(실제 작성자는 원청 계정으로 기록)
   - 위험성평가, TBM, 지적조치, 사진, 사용자 지정 기록의 업체별 접근 제한
   - 기존 업체 미지정 기록은 자동으로 아무 업체에도 배정하지 않음

4. 대시보드 / 지적·조치 / 사진
   - 오늘 신규, 주간 통합 미결재, TBM 미결재, 이번 주 미등록 업체, 미조치, 확인 대기
   - 지적사항과 조치관리 내용을 동일 기록번호로 연결
   - 협력업체 조치완료 등록 -> 원청 현장관리자 최종 확인
   - 조치 전·후 사진과 사진보관함 출처/작성자/원본 보기
   - 본사 최고관리자는 전 현장별 주간 미결재, TBM 미결재, 협력업체 수 확인

[사용 시작 순서]
 1. 최고관리자가 현장과 사용자 계정을 만들고, 사용자에게 현장 권한을 배정합니다.
 2. 원청 현장관리자가 [협력업체·작성자 관리]에서 협력업체를 등록합니다.
 3. 같은 화면에서 각 협력업체 직원의 소속 업체를 지정하고 [소속 저장]을 누릅니다.
 4. 협력업체 직원은 자신의 계정으로 위험성평가를 작성합니다.
 5. 협력업체 직원은 [주간 통합 결재]에서 본인 업체 작성 완료를 제출합니다.
 6. 원청 현장관리자는 해당 주차 평가 전체를 검토하고 상신·승인합니다.
 7. [승인 완료 평가서]에서 내용을 확인하고 PDF로 저장합니다.

[중요: 배포 전 확인]
 - 지금 운영 중인 Render PostgreSQL 데이터베이스를 최신 백업하세요.
 - Cloudflare R2 사진 원본은 PostgreSQL 백업에 포함되지 않습니다.
 - 운영 사이트가 아닌 테스트 DB/테스트 Render 서비스에서 먼저 검증하는 것을 권장합니다.
 - DB 변경은 기존 테이블/기록을 삭제하지 않는 추가형 마이그레이션입니다.
 - 이전 주간 평가서의 최초 스냅샷은 업그레이드 시점의 기록 내용으로 보존됩니다.
 - PostgreSQL Free 인스턴스 만료 예정일(2026-12-13)을 확인하고 데이터 이전/요금제 전환 계획을 마련하세요.
 - Render 환경변수 DATABASE_URL, SESSION_SECRET, R2_* 값은 GitHub에 올리지 마세요.
 - 새 DB에서 첫 관리자 생성 시 INITIAL_ADMIN_PASSWORD를 설정해야 합니다(기존 관리자 DB에는 영향 없음).

[배포 방법]
 GitHub 저장소의 기존 파일과 같은 경로로 아래 파일을 업로드합니다.
   server.js
   package.json
   public/index.html
   public/admin-center.html

 Render 자동 배포 완료 후 아래 순서로 시험합니다.
 - 원청 현장관리자 계정으로 로그인 / 협력업체·작성자 관리 메뉴 확인
 - 협력업체 직원 계정으로 로그인 / 다른 업체 기록이 안 보이는지 확인
 - 이번 주 위험성평가 작성 / 업체 제출 / 원청 통합 상신 / 승인
 - 반려 / 재상신 / 차수별 보고서 보존 확인
 - TBM 작성 / TBM 결재함 / 사진 출처 / 지적조치 확인
 - 기존 V5/V6 기록, 사용자 지정 양식, 기간별 검색 유지 여부 확인

[검증 상태 및 제한]
 - node 문법 검사, HTML ID/핵심 경로 검사, 주간 결재 흐름의 모의 테스트는 통과했습니다.
 - 실제 운영 PostgreSQL / Render / R2와 연결한 종단 간 테스트는 하지 못했습니다.
 - 보고서는 브라우저 인쇄용 HTML이며, 서버에서 자동 생성되는 서명 PDF가 아닙니다.
 - 전자서명 인증, 법정 서식 적합성, 대규모 동시접속/보안 전문 점검은 별도 검증이 필요합니다.
 - 관리자 센터의 기존 개별결재 기능은 과거 기록 보존을 위해 남아 있습니다.
   신규 위험성평가 결재는 반드시 [주간 통합 결재] 메뉴를 사용하세요.
 - 기존 기록 중 업체가 지정되지 않은 데이터는 현장관리자가 확인 후 보완해야 합니다.

[오류 발생 시]
 - GitHub에 비밀키를 올리지 마세요.
 - Render의 배포/서버 로그에서 에러 문구를 확인하세요(환경변수 값은 가리고 공유).
 - 문제가 있으면 DB 백업과 이전 버전 소스가 있어야 안전하게 복구할 수 있습니다.
